# Wayfarer world kit 0.3.0

An engine-neutral TypeScript starting module based on your biome themes and the supplied Reedhaven / Wayfarer screenshots. This is new, proposed world content. It does not replace or claim to reconstruct your running game's source, map, movement, combat, or networking. No runtime packages, connectors or credentials are required.

Version 0.3 adds three themed river crossings, dry fitted landings, continuous walkable ramps, shared construction meshes, placement reservations and a rendered construction atlas. See `CONSTRUCTION.md` and `CREATIVE_ATLAS.md`. Version 0.2 walking and navigation remain included (`WALKING.md`). Static terrain generation stays at version 1; construction has its own version 1.

## Run

Requires Node.js 22 or newer for the supplied commands. The core module uses standard JavaScript and can also be bundled into a browser client.

```sh
npm install
npm test
npm run demo
```

Already compiled: `node dist/example.js` and `node --test test/*.test.mjs` work without installing dependencies. The compiler used for this delivery is pinned in package.json. The dependency installation may need network access.

## Minimal usage

```ts
import { generateChunk, regionAt, weatherAt } from './src/world.js';
import { terrainMesh, landmarkPrimitives, waterCells } from './src/geometry.js';

const world = { seed: 20260928, generatorVersion: 1 } as const;
const chunk = generateChunk(world, 0, 0);
const terrain = terrainMesh(chunk);
const structures = landmarkPrimitives(chunk);
const water = waterCells(world, chunk);
const region = regionAt(world, 20, 20);
const weather = weatherAt(world, region, 300_000);
// Supply these buffers/descriptors to your actual renderer and collision builder.
```

Import `dist/*.js` instead when consuming the precompiled package outside a TS source tree.

## Renderer adapter

`ChunkView` mounts entering chunks and unmounts departing chunks. Implement `WorldRenderer.mount(chunk, biome)` and `unmount(chunkId)` in your renderer. In mount, build a terrain mesh from the returned vertex/index buffers, convert landmark and prop primitives to engine meshes (or map each kind to an asset). In unmount, remove meshes and release chunk-owned buffers, collision bodies and audio. Cache shared materials/assets separately so unloading one chunk does not destroy assets used by another.

Coordinates: X/Z horizontal, Y up, one unit assumed to be one meter. Chunks are 64 units square with 16x16 cells (4-unit spacing). Heights are row-major 17x17 samples including shared edges. Water depths are row-major 16x16 center samples. Terrain indices face +Y. Primitive sizes are full extents centered on their positions. Landmark positions are anchors at terrain height, not centers of their complete models.

Choose an origin offset before large-coordinate rendering to control float32 precision. Match or transform these coordinates to your existing game; do not overwrite Reedhaven's current coordinate system blindly.

## Client/server contract

1. Server owns `WorldConfig` and sends a `world.manifest` through an authenticated transport.
2. Client requests a chunk using `encodeMessage({schema:1,type:'world.request',cx,cz})`.
3. Server calls `answerChunkRequest(text, world, authenticatedPlayerPosition, serverTimeMs)`.
4. Client decodes the returned recipe through `chunkFromMessage(reply, expectedWorld)` and builds the geometry.
5. Server independently generates the same static descriptors for its collision implementation.

Only seed, coordinates, version and server time cross this protocol. Requests cannot supply terrain, loot, player positions or authoritative state. Input JSON is capped at 1024 UTF-8 bytes and rejects unknown/missing fields. Coordinates are integer bounded. Requests beyond two chunks from the server-owned player position are rejected.

This is a STATIC world recipe protocol, not a complete multiplayer server. Add authenticated sessions, transport frame limits before buffering, request rate limits, interest subscriptions and reconnect behavior in your actual server. Treat transport data as untrusted even if it decodes correctly. Player movement, collision, gate state, resource depletion, loot, combat and persistent changes must stay authoritative on the server. Do not derive rewards or movement acceptance from client-generated geometry. Static biome seeds are public here; do not encode secrets in them.

Bump generatorVersion whenever generation rules, dimensions, catalog ordering or landmark generation change. Both client and server must deploy matching code/catalog versions. Runtime math is repeatable in the tested Node runtime; cross-engine transcendental floating-point results are not promised bit-for-bit. Quantize or transmit authoritative geometry if your engine needs bit-exact collision across runtimes.

## Implemented versus proposed

**Implemented:** ten region recipes, smooth blended heightfield parameters, a winding river corridor with biome-weighted carving, reproducible prop placements, clear crossing-trail strips, landmark exclusion space, per-epoch weather metadata, mesh buffers, blockout geometry and validated recipe exchange.

**Blockouts:** stronghold walls with an open gate arch; garden fencing with an approach opening; stepped red-sand pyramid; barrow mound and grave markers; column shrine; bridge deck/rails; two village huts. No image textures or third-party models are bundled. Terrain currently uses one base color per chunk; an engine adapter can blend material colors across region boundaries.

**Requires host implementation:** real materials/textures, glyph art, NPC AI, gathering, hazards, audio playback, weather particles, full physics/navmesh, gate authorization and terrain editing. The new walker supplies bounded heightfield navigation and static AABB collision, not a complete physics engine. Resource names, encounters and ambience are symbolic catalog keys, not spawned gameplay systems. The procedural river is a single winding corridor, not a continent-wide hydrology simulation. Cavern currently provides an open heightfield theme; it is not enclosed cave geometry. Water planes approximate wet cells and need shoreline fitting for polished visuals.

Legacy random landmarks are NOT terrain-fitted or guaranteed navigable: flatten/validate pads, slope access and foundations in the engine before enabling collision. The original random bridge blockout is not positioned/fitted across a river; the new `planCrossing` system supplies separate validated crossing sites. Village blockouts are solid decorative huts with no interiors. Trail strips reserve prop-free space but do not yet create roads or bridges over water. Prop blockouts now provide shared collision dimensions, but placement does not yet prevent overlap between props. Treat generated chunk objects as read-only after construction.

## Safe first integration

Add this beside the existing game as an isolated test region. Keep the existing spawn, player controller, camera, UI and networking intact. Implement the renderer adapter, then match server collision and test movement over terrain, chunk transitions and reconnects. Upload your renderer entry point, server entry point, world/map module and package.json when ready for an actual integration patch.
