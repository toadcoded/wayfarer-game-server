# rc.17 character model integration

The existing createHero3D factory mounts these models everywhere the game already creates characters. All colors and proportions are derived from shared roster presets; server-controlled skin choice still selects the same model on all clients. Custom appearance is a strict, detached, frozen API object with bounded palettes/enums. Invalid input is rejected before allocating nodes. No arbitrary texture URL or client gameplay state is accepted.

The rig has16 transform pivots: pelvis, torso/trunk, head, jaw; bilateral hips, knees, ankles, shoulders, elbows and wrists. Knees flex toward the back during the swing cycle; elbows flex forward. Wrist parenting keeps weapons attached to the hand through gestures. Eyes blink, eyelids shift, lips/jaw and teeth support speaking/sneeze gestures, and pause resets secondary joints. Existing outfits remain layered over body contours; abdominal panels and spine seam are clothing details. Dermal detail means subtle per-vertex tonal variation, not pore maps or scanned skin.

Static geometry is merged per parent joint and material in local coordinates. Animated eyes/lids/teeth, joints and cape remain independent. Each batch retains feature names in metadata. Temporary construction references are cleared after assembly and equipment swaps do not append to construction arrays. All character meshes are non-pickable/non-colliding and do not change authoritative navigation or targeting. Shared material caches are bounded per rig and disposed with it.

Character Studio: /preview/characters.html; local appearance/pose preview only. Face view uses a short near clipping plane; whole-body view shows clothing and cape. Drag/pinch/scroll camera controls; rendering capped30fps/DPR1.5. Studio follows reduced-motion preference and disposes on page exit. No GPU/device claim is made because browser startup failed in the preceding rc.16 environment check and current validation uses NullEngine/stub DOM and actual HTTP/WebSocket tests.

Limits: no weighted skeletal skinning, blendshapes, fingers individually animated, lip-sync audio, production face texture/PBR maps, anatomical muscle deformation, hair strand simulation, appearance persistence or multiplayer custom appearance payload. Body builds and contours are stylized clothed silhouettes. Asset art-direction and physical-device visual checks are next steps.
