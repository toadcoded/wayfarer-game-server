# Wayfarer v0.7.5 — Atlas of Ten Reaches

A world atlas expansion of v0.7.4. Two browser tabs can join one server-owned Willowglass Causeway. This is an executable networking rehearsal, not a hosted MMO release.

## Explore the world atlas

Run `npm run preview`, then open http://127.0.0.1:8080/preview/atlas.html. The atlas links ten named realms to actual matching generated biomes, shows terrain sample thumbnails, and lets you browse planned travel itineraries. Dropdown and numbered buttons provide alternatives to map clicking. Both existing previews link to it.

Named places and dashed travel links are authored plans, not spawned settlements or traversable routes. The playable multiplayer area remains Willowglass Causeway. See WORLD-ATLAS.md and the generated WORLD-ATLAS.json catalog.

## Start the shared realm

Node 22+ is required (verified with Node 24.19.0). Install the pinned dependencies, then start:

```sh
npm ci --ignore-scripts
npm run realm
```

Open http://127.0.0.1:8081 in two tabs and press **Join realm** in each. Use arrow keys or the on-screen direction buttons. Your marker is gold; other players are blue. Both players initially spawn at the same landing, so move to separate them. The server owns movement, collision, player IDs and time. The server sends snapshots at approximately 10 Hz. The client renders buffered positions on animation frames with a 100 ms presentation delay. It interpolates known samples only; client-side prediction is not implemented.

Use the exact 127.0.0.1 URL printed by the server. The host binds only to loopback and does not accept a different hostname or Origin. A second physical device cannot connect to this loopback server. Do not expose it through a tunnel or change the bind address as a substitute for production security.

Disconnect removes that player. Joining again creates a new player at the landing. It does not resume a saved character. Stop the server with Ctrl+C.

The server supports up to eight local connections. There are no accounts, passwords, remote services, database migrations, persistent saves, or automatic reconnection.

## Movement presentation and stale connections

A bounded 32-snapshot buffer now smooths known positions without changing server authority. It rejects duplicate/out-of-order snapshots and backward arrival clocks, avoids rewinding its presentation timeline, removes departed players immediately, and clears all history on disconnect/rejoin. Large jumps over four world units and sample gaps over 500 ms snap to the newest position instead of drawing travel through the intervening world.

When updates stop, positions freeze rather than extrapolate. At 500 ms without a fresh snapshot the UI marks the connection stale and held directional input is cleared. At five seconds, the client closes and offers a manual fresh join. Repeated old snapshots do not refresh that deadline. Local and remote avatars both use the presentation buffer; the extra 100 ms delay is intentional and is not local-player prediction/reconciliation.

Static scenery stays cached; avatar positions redraw on requestAnimationFrame. Visual smoothness and physical-device behavior still need real-browser validation. See SMOOTHING.md for boundaries.

## Compatibility before gameplay

The WebSocket upgrade now requires the private `wayfarer.realm.v1` subprotocol. Before any player is created, the client sends a strict hello declaring its world/protocol contract. The server accepts only the matching protocol, seed, generator and scene revisions, coordinate convention, simulation interval and snapshot version. The welcome echoes that contract and assigns a server-owned player ID.

Malformed, mismatched and silent pending clients are rejected. Pending connections count toward capacity and expire after five seconds. Existing v0.7.2 clients must be updated; they do not implement this handshake. This checks a declared compatibility contract, not every byte of a build, and it is not authentication.

Use INTEROPERABILITY.md for the wire flow and REALM-CONTRACT.json for a generated, machine-readable reference. The shared TypeScript/JavaScript module is exported as `./realm-contract` for adapters. No imported Ashfen or other reference branch has been automatically connected.

## Earlier transport wiring

- src/realm-scene.ts: one deterministic world recipe and collider setup for server and network client.
- tools/realm-server.mjs: loopback HTTP/WebSocket adapter, server-owned timer, per-recipient snapshots and cleanup.
- src/realm-client.ts and preview/realm.html: manual connection lifecycle, strict snapshots, direction input, authoritative avatar rendering and cached static scenery.
- test/transport.test.mjs: real socket integration and rejection cases.
- test/network-client.test.mjs: browser-client module exercised with a stub DOM and real WebSocket connection.

Existing terrain, construction, pathfinding, session rules and permanent fail-stop fault handling remain included. Original ZIPs are unchanged; reference-source branches remain excluded from compilation and execution.
