# Wayfarer v0.7.1 — fault-boundary stabilization

A runnable expansion of the preserved v0.4 scaffold. This release implements a focused subset of the saved v0.7 research design from source, with a fresh test run. It is not the missing working tree described by that report.

## Play locally

Requires Node 22 or later. Compiled JavaScript is included; no install is needed to run the preview:

```sh
npm run preview
```

Open http://127.0.0.1:8080. Tap terrain to travel, use arrow keys, or press **Cross bridge**. Choose Willowglass, Saffron or Mothlight. **Pause** freezes the local simulation; **Resume** discards time spent paused. The health readout shows simulation ticks and discarded catch-up time. This is an offline, in-process demonstration, with no remote players, accounts or network connection.

To rebuild and test:

```sh
npm ci --ignore-scripts
npm test
npm run demo:realm
```

`demo:realm` runs two independent simulated players against a garden wall and prints an encoded/decoded snapshot. It demonstrates realm behavior without pretending to be an Internet multiplayer test.

## v0.7.1 stabilization

A thrown simulation step now permanently faults that session and realm. Partial internal updates are not rolled back; instead, state reads, snapshots, joins, further ticks and clock reset are rejected. Inputs return false. Disconnect cleanup remains available. The trusted host must discard the failed instance and create a new realm from a separately validated checkpoint or known spawn. No persistent checkpoint recovery is implemented yet.

The realm exposes `status` as `active` or `faulted`. Invalid elapsed-time arguments are rejected without faulting a healthy realm. A throwing trusted `beforeTick` hook does fault the realm, because it may already have mutated host state.

The local preview catches simulation failures, displays a stopped message and lets Return rebuild the local scene. This is a local scene restart, not recovery of a networked or persisted character.

See RELEASES.md for artifact lineage and VERIFICATION.md for current evidence.

## Earlier v0.7 additions

- **Fixed 20 Hz simulation:** a bounded accumulator runs at most four ticks per host advance. A long stall drops excess elapsed time instead of accumulating simulation debt. Render frames use requestAnimationFrame independently.
- **RealmRuntime:** server-owned connection mapping, public player IDs, simulation clock, join/leave lifecycle, and visibility-filtered snapshots.
- **Snapshot codec:** exact fields and version, consistent tick/time values, bounded bytes and coordinates, duplicate rejection, player count limits, and copied state.
- **Transport queue policy:** projected outgoing queue size determines send/drop/close decisions. Cosmetics are dropped at soft pressure; every priority closes at hard pressure. This policy is not yet connected to a real socket.
- **Preview lifecycle:** pause/resume, hidden-tab reset and a simulation health readout. The three crossings retain the existing prop collisions and pathfinding.
- **Flood counter:** rejected packets no longer increase the per-tick packet counter indefinitely.

## Integration contract

World coordinates use X/Z on the ground plane and Y for elevation. Use the existing coordinate adapters when interpreting reference branches.

A production host must authenticate a connection, select its spawn, call `realm.join(connectionId, spawn)`, route input strings through `realm.receive(connectionId, packet)`, and call `realm.advance(elapsedMs)` from a monotonic server timer. Packets must never supply elapsed time or drive the clock. Use `realm.snapshotFor(connectionId)` and `encodeRealmSnapshot()` for outbound state. Call `realm.leave(connectionId)` when a connection is removed.

`beforeTick` is a trusted local host hook for the preview/bots, never a network callback. Snapshot player IDs deliberately differ from private connection identifiers. Rejoining produces a new public ID and resets input sequence scope; resumable sessions are not implemented. Visibility filters horizontal distance, not line of sight or separate dungeon instances.

The low-level `WorldSession` remains available for compatibility. Its host owns tick scheduling; the preview now uses `RealmRuntime` instead. Runtime authority in the browser preview is local and can be modified by that browser's user. Real authority requires hosting the runtime separately.

## Remaining work

No hosted WebSocket service, authentication, persistent saves, combat/economy authority, remote smoothing, prediction/reconciliation, reconnection recovery, adaptive quality system, responsive HUD module, new twelve-region world graph, or budgeted interest streaming was added in this pass. The earlier chunk view remains as-is. The report proposes those systems; this release does not claim them.

The preview remains a schematic canvas renderer. Painter ordering, always-visible player drawing, minimap detail, mobile performance and real-device usability need further work. Real multiplayer load tests and physical-device QA remain outstanding.
