# Wayfarer v2.6.0 — Implementation Plan

## Source and release

- Use the checksum-verified Drive v2.5 package as the cumulative code base, retaining its v2.3 and v2.4 features.
- Bump the package and served release identity to **2.6.0**; do not represent v2.6 as already visually tested.
- Keep the live package ZIP above 50 MB and publish the complete runnable package at the temporary site.

## Requested product changes

- Enrich graphics, objects, animals, buildings, characters, color variation, UI/HUD, canvas presentation, ground, and mountain/building visual thickness.
- Make characters slightly smaller and increase walk, jog, and run speed modestly.
- Add server-authoritative melee styles: slash, crush, strike, and lunge; add ranged projectiles with damage resolved after a tick-based flight; expose multiple magic spell choices.
- Add skeleton, zombie, thug, bandit, and mugger encounters in distinct world regions. Skeletons have a 5% steel-warhammer drop; zombies have a 5% steel-battleaxe drop; thugs/bandits/muggers have 5% drops for steel daggers/swords/rapiers respectively.
- Make the thug campsite a multiplayer multi-combat zone: nearby members can aggro together, attack and pursue players, while leashing, defense, protection prayer, and spacing allow counterplay.
- Keep combat, projectile timing, drops, and loot server-authoritative, deterministic/replayable, validated, and bounded.

## Architecture and persistence

- Reuse v2.5 movement, navigation, combat, prayer, inventory, and multiplayer contracts rather than building a parallel game.
- Add a typed hostile-world module for camps, NPC state, projectile clocks, loot, aggro/leash rules, damage, and deterministic drops; connect it through `GameActions` and `RealmRuntime`.
- Add the steel weapons to the existing inventory/equipment catalog. Keep the saved-player record shape and SQLite schema unchanged so old player profiles remain readable.
- The stopped temporary runtime database has 10 profiles and SQLite `user_version=1`; a byte-for-byte directory backup was created at `runtime-pre-v26-backup-2026-10-07` before further work.
- Keep the public package and temp site aligned to the same v2.6.0 source/build. The temporary public URL is not an always-on hosting promise.

## Visual direction

Keep the existing realm identity and build on its low-poly adventure style: richer silhouettes, layered terrain/building foundations, varied natural/metal pigments, clearer combat markers, readable health/target status, and restrained motion. Preserve the established camera and touch controls; the 3D scene remains a presentation of the authoritative shared simulation, not a separate rules engine.

## Package and deployment scope

Build/test the source, create a complete ZIP at least 50,000,000 bytes with a matching SHA-256 sidecar, and deploy the same v2.6.0 package to the current temporary sandbox website while reusing the saved-profile directory only after testing against the backup copy. Verify HTTP health, served version, client assets, public WebSocket handshake/game-state, archive download length/hash, and the main gameplay/UI in a browser. Report any remaining limitations honestly.
