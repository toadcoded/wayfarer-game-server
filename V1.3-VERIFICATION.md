# Wayfarer v1.3 verification — smoother characters, open navigation and storage UX

Verification date: 2026-10-05 UTC.

## Build and tests

- Node.js: **v24.19.0**; npm: **10.9.2**.
- `npm test` — canonical TypeScript/Babylon/PGlite/character build completed, then **337 passed, 0 failed**.
- `npm run assets:validate:py` — **8/8 assets validated**.
- Updated interoperability manifest exports simulation revision **17**, scene revision **4**, and selective deposit/withdraw examples.

## Gameplay and UI coverage

- Shared map scene measures **150 × 128 world units**, with spaced, walkable landmark clearings and a deliberately small five-tree orchard; the generated scene produced 143 shared obstacle/decorative primitives in the measured run.
- The five visible orchard trunks use the same deterministic centers as server trunk colliders. Tests confirm a straight crossing is blocked and the shared pathfinder routes around a trunk using traversable segments.
- Ground and constructed walking surfaces are marked pickable; props, water and rails are not. Babylon ground picking and isometric fallback both map clicks into pathfinding. Direct keyboard/direction movement cancels the queued walk route.
- Character construction and renderer tests pass with the higher-tessellation, rounded body/tunic changes.
- Selective resource deposits/withdrawals are tested for partial and all-that-fits amounts, bank-cap boundary behavior, storage bounds, camp-only range, conservation, and atomic rejection when a bank/resource/pack capacity check fails. The item pack exposes 20 clickable equipment slots; the resource pack retains its authoritative 12-unit cap.
- Existing socket, origin/cookie, persistence, guest enrollment, process restart and asset-serving tests remain green.

## Hosting and review boundary

This verifies source, builds, deterministic simulation behavior, integration tests and the bundled assets. It is not a physical iPhone/Android/GPU review. The Render deployment remains uncreated because Render requires billing details. Any live Sandbox preview remains a temporary, non-guaranteed demo endpoint; it is not a permanent production host. Guest cookies are still the only character identity/recovery mechanism.
