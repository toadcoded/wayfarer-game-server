# Polycodex / Copper Lantern Canonical Filing Index

This index describes the intended role of each numbered project area in the linked Drive root.

| Area | Purpose |
|---|---|
| `00_AUDIT_AND_PROVENANCE` | Source inventories, audit snapshots, quarantine notices, and provenance evidence |
| `00_INDEX_AND_GUIDANCE` | Canonical project orientation, readmes, and navigation guidance |
| `01_CLEAN_ROOM_PHASE_1` | Clean-room architecture, source boundaries, and Phase 1 implementation records |
| `01_TASK_MANAGEMENT` | Task plans, execution notes, and milestone coordination |
| `02_VALIDATION` | Tests, hashes, smoke checks, and verification artifacts |
| `03_FORMATTERS_AND_TEMPLATES` | Reusable formatting, templates, and generation helpers |
| `04_CONNECTOR_REGISTRY` | Connector manifests, integration records, and service configuration notes |
| `05_CHANGE_LOGS` | Historical change logs and dated delivery records |
| `06_10_10_OPTIMIZATION` | Current Drive audit, canonical index, and optimization follow-up queue |
| `99_QUARANTINE_EXACT_DUPLICATES` | Reversible holding area for older byte-identical same-name copies |

## Root-level policy

New durable project artifacts should be filed into the numbered area that matches their purpose rather than remaining at the root. Root-level source files should be retained only when they are the current canonical delivery or are awaiting classification.

## Review queue

Large archives and differently named aliases remain intentionally unmodified. Their next review should compare project lineage, archive contents, and current source references before any move or archive decision.
